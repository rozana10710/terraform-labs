THE WORKFLOW

One loop you’ll run every day.

Write the code, preview the change, apply it. Then repeat.

STEP 1
terraform init

Downloads the providers. Run it once per project, and again when providers change.

STEP 2
terraform plan

Shows what will change. Nothing is created yet.

STEP 3
terraform apply

Shows the plan again, asks for yes, then makes the changes.

STEP 4
terraform destroy

Removes everything Terraform created. Always clean up labs.

Read the plan before you type yes.
+create ~update -/+replace -destroy

HCL BASICS

Every block has the same shape.

resource1 "aws_vpc"2 "main"3 { cidr_block = "10.0.0.0/16"4 } # address: aws_vpc.main
1

Block type — what it is: resource, data, variable, output.

2

Resource type — comes from the provider (aws_…).

3

Local name — yours. Used to refer to it in code.

4

Arguments — settings, written as name = value.

REFERENCES

Blocks point to each other

vpc_id = aws_vpc.main.id

Terraform sees the link and creates the VPC first. You never set the order.

RESOURCE VS DATA

Create or read

resource creates and manages something.
data only reads something that already exists.

Bonus: build it one piece at a time with -target.

$ export AWS_PROFILE=tf_demo
$ terraform init
$ terraform plan
$ terraform apply -target=aws_vpc.main
$ terraform apply
$ terraform destroy   # don’t skip this
